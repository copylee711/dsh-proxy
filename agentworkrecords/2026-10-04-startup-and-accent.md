# 2026-10-04 启动耗时与共用强调色（0.4.2）

## 背景

用户反馈 DSH 桌面版启动偏慢，要求排查是否由自己的插件造成并优化；同时统一各插件的强调色选择。

## 排查结论

在隔离的 `dsh web` 宿主里逐个加载插件计时。本插件宿主端的耗时几乎全部来自导入 undici（自带一份 8.x，独立于宿主），约 150 ms；插件自身代码很小。

## 改动

- `src/undici.ts`：undici 改为首次使用时用 `createRequire` 同步加载，不再随插件导入。
- `src/provider-routes.ts`：路由表里的 dispatcher 改为首次读取时才创建（同一代理地址仍共用一个）；`close()` 只关闭已创建的。没有被请求用到的路由不会触发 undici 加载。
- `src/fetch-router.ts`：发起被路由的请求时才取 undici 的 `fetch`。
- 设置页接入共用强调色：`src/client/accent.ts`（与其他插件内容相同），主按钮、选择菜单焦点框改用 `--cl-accent`，页面底部增加强调色选择；中英文案补充。
- README 去掉 npm 发布流程，系统代理说明并入“使用”一节。

## 结果

- 宿主端导入：约 150 ms → 约 16 ms（本机 Node 24 单独导入 `lib/index.js` 三次取值）。配置了提供商代理的用户，undici 的加载推迟到该提供商的第一次模型请求。
- `npm run typecheck`、`npm test`（33 项）通过；`lib/`、`client/` 已重新构建并提交。

## 未验证

- 没有用真实代理跑端到端请求；路由逻辑由现有的本地假代理测试覆盖。
